## What S7 fixed about the write API (the builder must follow it)

- One save endpoint pair: `POST /invoices` (new) and `PUT /invoices/:id` (draft, posting a draft, editing a posted invoice) with `mode: "draft" | "post"`. **A PUT must carry the `revision` of the invoice as loaded**; a stale one is refused
  with "This invoice was changed by someone else since you opened it. Reload it and make your change again." — show it verbatim and reload. Send `idempotencyKey` (8-100 chars) on every save.
- Lines are `{id?, productId, quantity, unitPriceP, discountP?, taxRatePct? | taxP?, warehouseId?, unit?, batchNo?, notes?}`; send the line's `id` back for lines that stay (keeps their identity). Quantity: at most 3 decimals.
  Live totals: the shared `invoiceTotals` (`qtyToMilli(quantity)` for the quantity).
- `paidAmountP`: a NEW invoice defaults to 0; editing a posted invoice defaults to what is already received; a DRAFT cannot carry one (refused: "Payment can only be taken when the invoice is posted…" — disable the field for drafts);
  lowering it below the money received is refused naming the receipt. It also needs `PAYMENT_CREATE` — the server answers 403 for the whole save.
- A posted invoice cannot go back to a draft; its shop cannot change while editing (use Change shop). Both come back as 422 with the server's wording; the screen should not offer them.
- `GET /invoices/:id` → `actions.*` gives `{allowed, reason}` per role and state (cancelled / return / dispatch / money received / permission) — render disabled buttons with the reason, never re-derive it.
- **SALES cannot cancel a posted invoice** (`TRANSACTION_CORRECT`) but **can discard a DRAFT** (owner decision 2026-09-24; done in S8 step 0) — offer "Discard draft" to `SALES_CREATE` holders, "Cancel invoice" only to `TRANSACTION_CORRECT`; render from `actions.cancel`, never re-derive.
- Pickers: `GET /products` (`available[]` per warehouse, `sellP`, `lastRateP`; cost fields only for `PROFIT_VIEW`), `GET /warehouses`, `GET /customers` (S3 lookup).
- The invoice detail has **no** `paymentStatus` string beyond `UNPAID | PARTIAL | PAID` (derived) and the legacy `status`.

## What S8 built about the read API (the list, print and profit screens follow it)

All shapes are Zod schemas in `@farooq/shared` (`schemas/invoice-list.ts`, `schemas/invoice-print.ts`, `schemas/invoices.ts`) — parse responses with them, as S5 does. Reads need any of `SALES_CREATE | TRANSACTION_CORRECT | COLLECTION_VIEW | FINANCIAL_REPORT_VIEW`
(OWNER, MANAGER, ACCOUNTANT, SALES; the warehouse role gets 403 — hide the nav item, show "Not available for the Warehouse role" on a direct URL like S5). Money is paisa, dates `YYYY-MM-DD`, quantities are bags.

- **`GET /invoices`** — query: `q scope status regionId warehouseId from to minP maxP sort limit offset` (all optional; a blank value is "no filter"; unknown fields are 422). `scope` ∈ `all number customer product amount payment notes` (labels `INVOICE_SEARCH_SCOPE_LABELS`),
  `sort` ∈ `newest oldest high low due` (`INVOICE_SORT_LABELS`), `status` ∈ the eight legacy strings (`INVOICE_STATUSES`, words `INVOICE_STATUS_LABELS`), `minP` / `maxP` on the grand total in paisa (parse the box with `parseRupees`). **There are no presets on the server**: "Today / This week / Last 30 days…" are the screen's arithmetic
  (`apps/web/src/lib/periods.ts`) sent as `from` / `to`; keep the state in the URL as the payments screen does. Response: `items[]` (`id number orderNumber date status paymentStatus customerId shopName ownerName region warehouse itemCount quantity subtotalP discountP chargesP totalP paidP outstandingP hits`),
  `total`, `limit`, `offset`, `onFile`, **`interpreted`** (`terms`, `dates[]` with `label / src / dayFirst`, `dateFilterReplaced`, `problems[]` — draw these as the legacy did: "“12/09/2026” is read as 12 Sep 2026 (day / month / year) — this replaces the date filter", and the warning banners; a list with `problems` is empty on purpose),
  **`kpis`** (`count drafts invoicedP receivedP outstandingP` — the four legacy cards, over the WHOLE filtered list, drafts and cancelled excluded, `drafts` = every draft on file), **`statusFacets`** (`{count, totalP}` per status under every filter except the status one — for a status picker with numbers), and per row **`hits`** (`lines[{name, quantity}]`, `more`, `pays[]`, `morePays` —
  draw "Taj Mahal Sella × 20 · +1 more · Paid by REC-2026-000031 (4471)" under the invoice number as the legacy did). A draft has `number: null` — show "Draft".
- **`GET /invoices/export.csv`** — the same filters (no `limit` / `offset`), every match; download it as the payments CSV is (S5), the file name is in `Content-Disposition` (`farooq-co-invoices-<business date>.csv`).
- **`GET /invoices/:id/print?template=classic|standard`** — the document model (`InvoicePrint`). Both layouts draw the SAME model; `template` is the one the business chose (`classic` is the live setting) unless overridden. Fields you draw: `company` (block), `party` (BILL TO), `meta[]` (**skip rows whose `value` is empty**, as the legacy did), `strip[]`, `columns[]` + `rows[]`,
  `itemsFooter`, `totals[]` (`text` is the legacy "PKR 3,470" with "− " on discounts; `big` / `bold` / `rule` are style flags), `amountInWords`, `payments[]`, `ledger[]` (previous balance frozen, current outstanding live), `signatures`, `footer {thanks, terms, bank}`, `labels` (the wording — print these, do not retype),
  `isDraft` / `hasNumber` / `cancelled` (ribbon / stamp: `labels.ribbon`), and **`classic`**: `serial` (0 for a draft → print "—"), `invNo` (`SLV-000123`), `idNo`, `contact` ("Nil" when none), `regionUr`, `remarks`, `phones[]` (the Urdu header line), `ledgerRows[]` (the shop's last six account rows up to this invoice: `date` is already `dd/mm/yyyy`, `dr` / `cr` are plain figures, "0" when none),
  `ledgerTotals`, `box[]` (six rows; the fifth is blank on the shop's sheet), `qtyTotal` (print with ".00" as the legacy did), `lineTotal`. The Urdu strings are in `CLASSIC_LABELS` / `INVOICE_PRINT_LABELS`; **A4 portrait, one page for a typical invoice, paper colours fixed in any theme** (as the S5 receipt).
- **Profit:** `GET /invoices/:id/profit` (403 without `PROFIT_VIEW`) and `profit` in `GET /invoices/:id` **only for those roles — the key is absent otherwise, so `"profit" in detail` is the check, not a null test.** Per line `costKnown`, `revenueP`, `costP`, `profitP`, `marginPct`, `markupPct` (all null when the cost is unknown — show "cost unknown", never 0);
  per invoice `profitP` (null when no line has a known cost), `marginPct`, `complete`, `unknownCostLines`. Definition: goods margin net of the discount given; tax and charges are not margin (STATUS "Profit definition"). Price / below-cost hints in the builder use `costP` / `buyP` from `GET /products` (PROFIT_VIEW only), not this.
- **Statements:** invoice rows have `detail` (the legacy Description text), `qtyInfo`, `qtyLabel` ("500", "500 (mixed units)", "—"); other rows `detail: null`, `qtyLabel: "—"`. `description` is unchanged (the ledger wording S5 draws) — S9 may switch the Description column to `detail ?? description` and add the Qty column (screen + CSV + print) as long as S5's tests stay green.
- **Receive panel:** `GET /customers/:id/outstanding-invoices` rows have `lineSummary` ("200 × Zam Zam 20KG @ PKR 2,700" / "3 items — 500 total qty" / "").
- Statement and print ordering: an invoice always precedes the receipt taken with it (S8 fixed a tie in `journal_entries.created_at`).

## Scope (summary — the hub details it before S9 starts)
- **Invoices list** (`/invoices`): search + scopes + filters + sorts + KPI cards + status counts + paging + CSV; row actions per role and per
  `actions.*` with server reasons (from `GET /invoices/:id`, or an `Open` link — the list rows do not carry `actions`).
- **Builder** (`/invoices/new`, `/invoices/:id/edit`): shop picker never pre-selected (region filter), header warehouse + per-line warehouse,
  product search, qty/rate/discount per line (strict parsing, Urdu digits), live totals via shared `invoiceTotals`, stock "N available" / "short
  by N" hints, price hints (+ margin hints for `PROFIT_VIEW`), charges, Amount Paid (disabled without `PAYMENT_CREATE`), Save draft / Save, idempotency
  key, server errors verbatim, unsaved-changes guard. A posted invoice opens in edit only for `TRANSACTION_CORRECT` and shows the
  "adjusts stock and balance by the difference" warning; shop locked (→ Change shop).
- **View + print** (`/invoices/:id`, `/invoices/:id/print`): classic and standard from the one model, A4, fixed paper colours, Urdu labels, one page for
  typical invoices; cancel / discard-draft / duplicate / change shop dialogs; the profit block for `PROFIT_VIEW`.
- **Statements / Receive panel** show S8's invoice detail (Description `detail`, Qty column, `lineSummary`).
- **Tests:** Vitest for builder logic (preview = shared totals, parsing, never-pre-selected, permission visibility); Playwright e2e for create draft →
  post with payment → receipt + stock + statement agree; many drafts; stock refusal; edit posted up/down (stock and balance move by the difference);
  edit refused after return; cancel refused with receipt, allowed after reversing it; discard a draft as SALES; change shop; duplicate; role matrix; search spot checks against the API;
  CSV; print PDF one page (read back with pdf.js like the receipt); 390 px / dark / no console errors; screenshots reviewed; "not seen by a person" list; M2 summary with reconciliation numbers.
  **The e2e dataset must grow:** the S4 synthetic backup's 96 invoices have no lines — build the e2e dataset from `apps/api/test/helpers/synthetic-invoices.ts` (300 invoices with lines, reconciles with 0 differences) or extend it.
