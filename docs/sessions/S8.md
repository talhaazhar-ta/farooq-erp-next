## Scope
- **`GET /invoices`** on the S4 engine (`fold_search`, generated search columns, `parseSearchQuery`): filters status / region / warehouse /
  period / amount (on grand total); sorts newest/oldest/high/low/due; `interpreted`, `problems`, KPI totals (count excl. drafts/cancelled,
  drafts count, invoiced, received, outstanding) and per-status counts; row `hits` (matching product lines "name × qty", receipts "Paid by REC…").
  **Parity:** a literal JS reference of legacy `build` + `matcher` + sorts over legacy-shaped JSON; same ids, same order, same totals on the
  fixture, a seeded ~300-invoice synthetic backup with lines, and the real backup.
- **`GET /invoices/export.csv`** — legacy columns (Invoice, Date, Shop, Owner, Region, Warehouse, Items, Bags, Subtotal, Discount, Charges, Grand total,
  Paid, Balance, Status), BOM, injection guard, file name `farooq-co-invoices-<date>.csv`.
- **`GET /invoices/:id/print?template=classic|standard`** — the document model (company block from `company_profile`, bill-to snapshots,
  lines, totals rows only when non-zero, grand total / amount paid / balance on this invoice with Urdu labels, amount in words, payments against
  it, previous balance (frozen) and current outstanding, signature labels, footer/terms). Classic: `SLV-` digits, last 6 ledger rows up to this
  invoice. Draft → "DRAFT" and no number; cancelled → stamped.
- **Profit** (`PROFIT_VIEW` only; 403 otherwise, never leaked in other responses): per line and per invoice from `cost_snapshot_p`.
- **Statement detail:** invoice rows get the legacy description (typed description, else one-line "200 × Name pack @ PKR 2,700" / "N items — X total
  qty") and a Qty column; update S4's statement response additively; S5 screens keep working.
- `outstanding-invoices` rows gain a line summary (for the Receive panel).
