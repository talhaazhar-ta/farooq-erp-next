- **Already existing endpoints (do not rebuild):** `POST /invoices` (`mode: "draft" | "post"`), `PUT /invoices/:id` (edit a draft, post a draft, edit a posted invoice; needs the `revision` the client loaded),
  `POST /invoices/:id/{cancel,duplicate,change-shop}`, `GET /invoices/:id` (the detail: header, `shop` snapshots, `lines`, `receipts`, `stockMovements`, `actions {edit, cancel, changeShop, duplicate}` each
  `{allowed, reason}`), `GET /products?q&warehouseId&limit` (picker: names, brand, `sellP`, `minSellP`, `lastRateP`, `available[]`; `costP` / `buyP` only for `PROFIT_VIEW`), `GET /warehouses`.
  **S8 adds** `GET /invoices` (list), `GET /invoices/export.csv`, `GET /invoices/:id/print` — declare `export.csv` BEFORE `:id` in the controller (as payments do) and reuse `INVOICE_READ_PERMISSIONS`
  (`SALES_CREATE | TRANSACTION_CORRECT | COLLECTION_VIEW | FINANCIAL_REPORT_VIEW`; INVENTORY gets 403).
- **Quantities:** requests use `quantity` (decimal bags, at most 3 decimals); responses give BOTH `quantity` and exact `qtyMilli`. Money is paisa everywhere. `paidP` is derived from POSTED receipts' allocations (not stored);
  `balanceP = total − paid`; `outstandingP` also subtracts non-cancelled customer-return credit. Status strings are the legacy ones (`DRAFT`, `CONFIRMED`, `PARTIALLY_PAID`, `PAID`, `CANCELLED`, `DISPATCHED`, `PARTIALLY_RETURNED`, `RETURNED`).
- **Cancelled invoices** keep their `INVOICE` journal entry and get an `INVOICE_CANCEL` one dated the invoice's date; **statements already omit both** and report `omittedCancelled` (additive to `omittedReversed`). Any S8 search
  KPI (invoiced / received / outstanding) must exclude CANCELLED and DRAFT exactly as the legacy does — the journal is NOT the source for the invoice list (use `invoices` + allocations).
- **Search columns:** `invoices.search_number` exists (S4). Anything else the invoice search needs (customer name, product lines, notes, amount) needs a NEW generated column or a query over `invoice_items` / `customers`
  — add it in a new migration (`0007`); do not edit `0004`–`0006`.
- **Print model inputs already stored:** shop / region / warehouse snapshots on `invoices`, product snapshots and `cost_snapshot_p` on `invoice_items`, frozen `previous_balance_p` (signed), `payment_method`, `reference_no`,
  `notes`, `description`, `salesperson`, `due_date`. Receipts on an invoice: `GET /invoices/:id` → `receipts[]`. The company block comes from `company_profile` as for receipts (S4).
- **Profit:** `cost_snapshot_p` is `costOf` at the time of the last save (re-taken on every edit, like the legacy); 0 = unknown. `avgCostP` is never maintained until M4 — profit uses the snapshot, as the legacy did.
- **Invoice ↔ stock** for search hits ("Paid by REC…", matching product lines) can read `receiptsOn` / `invoice_items` directly.
- **Idempotency:** `request_keys` (kind `INVOICE`) — reads never touch it.

## Scope
- **`GET /invoices`** on the S4 engine (`fold_search`, generated search columns, `parseSearchQuery`): filters status / region / warehouse /
  period / amount (on grand total); sorts newest/oldest/high/low/due; `interpreted`, `problems`, KPI totals (count excl. drafts/cancelled,
  drafts count, invoiced, received, outstanding) and per-status counts; row `hits` (matching product lines "name × qty", receipts "Paid by REC…").
  **Parity:** a literal JS reference of legacy `build` + `matcher` + sorts over legacy-shaped JSON; same ids, same order, same totals on the
  fixture, a seeded ~300-invoice synthetic backup with lines, and the real backup.
- **`GET /invoices/export.csv`** — legacy columns (Invoice, Date, Shop, Owner, Region, Warehouse, Items, Bags, Subtotal, Discount, Charges, Grand total,
  Paid, Balance, Status), BOM, injection guard, file name `farooq-co-invoices-<date>.csv`.
- **`GET /invoices/:id/print?template=classic|standard`** — the document model (company block from `company_profile`, bill-to snapshots,
  lines, totals rows only when non-zero, grand total / amount paid / balance on this invoice with Urdu labels, amount in words, payments against
  it, previous balance (frozen) and current outstanding, signature labels, footer/terms). Classic: `SLV-` digits, last 6 ledger rows up to this
  invoice. Draft → "DRAFT" and no number; cancelled → stamped.
- **Profit** (`PROFIT_VIEW` only; 403 otherwise, never leaked in other responses): per line and per invoice from `cost_snapshot_p`.
- **Statement detail:** invoice rows get the legacy description (typed description, else one-line "200 × Name pack @ PKR 2,700" / "N items — X total
  qty") and a Qty column; update S4's statement response additively; S5 screens keep working.
- `outstanding-invoices` rows gain a line summary (for the Receive panel).
