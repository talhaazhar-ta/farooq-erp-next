## Corrections after S12 (read first — they win over the draft text below)
The builder talks to S12's API (`POST /purchases`, `PUT /purchases/:id`; schema `savePurchaseSchema` in `packages/shared/src/schemas/purchases.ts`; the tests in `apps/api/test/purchases-*.test.ts` show every body):
- **The body is the whole form, every time.** An edit is a full PUT with `revision` (the value read with the detail; missing = refused, stale = refused with the server's words). Fields left out are cleared, except `description`
  (kept when omitted) and `paidAmountP` (defaults to what is already paid). Build the edit body from the detail the way the test helper `purEditBody` does: carry `supplierInvoiceNo`, `vehicleNo`, `driver`, `deliveryRef`, `notes`,
  the overall discount (`invoiceDiscountP` on the detail), the three charges, and per line `id`, `productId`, `quantity`, `unitPriceP`, `discountP`, `taxP`, `warehouseId` — and `receivedQuantity` **only for a part delivery**
  (blank / absent = the whole line arrived; `0` = an order, nothing arrived; more than `quantity` is allowed). Line ids stay stable: send `id` for a kept line, omit it for a new one; a line left out is deleted.
- **`quantity` = bags ORDERED, `receivedQuantity` = bags that ARRIVED.** Show both columns; Received = 0 books the bill and no stock (the hint must say so).
- **Money:** `paidAmountP` above the total or below 0 is refused (new purchase too); on an edit it can only be **raised** (lowering is refused naming the voucher to reverse). A payment needs `PAYMENT_PAYOUT` — a role without it gets 403 and
  **the whole save is refused**, so the Amount-Paid box must be disabled for it. The voucher's reference is the supplier's bill number; the method defaults to Cash (`paymentMethod`).
- **The supplier lock is only known on save.** The detail has no "why can't I change the supplier" field: the server refuses a supplier swap with the legacy sentence when a POSTED voucher or a supplier return is attached. **S13 adds
  `actions.changeSupplier {allowed, reason}` to the detail (planned in the old draft as "the supplier lock shown")** so the builder can disable the picker with the reason instead of learning it from a refusal.
  Likewise a line with returned bags or a landed-cost share cannot be removed / re-producted: `returnedQuantity` is on the detail; `operationalShareP` only with `PROFIT_VIEW` — the server's refusal wording is the fallback.
- **Idempotency:** `idempotencyKey` (8–100 chars) on every save; the same key returns the first result (HTTP 200 on a create). A key already used by an invoice save is refused.
- **Cost display:** the averages and cost columns come back only with `PROFIT_VIEW` (absent keys). `GET /purchases/last-rates` gives the rate hint; a product with no purchase yet has none.

## Rules (each gets a test)
- **Supplier:** never pre-selected. Save is refused without one.
- **Received:**
  - blank means all;
  - 0 means the bill only, and the hint must say so, because it is the warehouse-app double-count trap;
  - at most 3 decimals.
- **Warehouses:** the header warehouse rewrites the lines' warehouse; a line's own warehouse changes only that line (S10's pattern).
- **Amount Paid:**
  - disabled without `PAYMENT_PAYOUT`;
  - on an edit it starts at what has been paid and cannot go lower, with the legacy hint verbatim.
- **Save:**
  - a double click sends one request;
  - the idempotency key is kept after a failure and renewed after a success;
  - a stale revision shows the server's words and offers Reload.
- **Edit:**
  - the legacy question comes first;
  - lines that have returns or landed costs show why they can't be removed;
  - the supplier's lock reason is shown.
- **Phone:** lines become cards under 768 px, with a sticky total and Save button, and no horizontal scroll.
