## The write API in one place
S9.md's section "What S7 fixed about the write API" is exact — read it first: `POST /invoices`, `PUT /invoices/:id` with the `revision` as loaded, `mode: "draft" | "post"`, `idempotencyKey`, line shape
`{id?, productId, quantity, unitPriceP, discountP?, taxRatePct? | taxP?, warehouseId?, unit?, batchNo?, notes?}`, `paidAmountP` rules, refusals as 422 `{message, errors[]}`, the pickers `GET /products` (`available[]`,
`sellP`, `lastRateP`, `minSellP`; cost only for `PROFIT_VIEW`), `GET /warehouses`, `GET /customers`. `INVOICE_MESSAGES` and `saveInvoiceSchema` are in `@farooq/shared`; live totals use `invoiceTotals` + `qtyToMilli`.

## Scope
- **Routes:** `/invoices/new`, `/invoices/$id/edit` (drafts and, for `TRANSACTION_CORRECT`, posted invoices; `actions.edit` decides), "New invoice" on the list (`SALES_CREATE` holders) and the draft's view page gets **Edit** and **Post**. **Duplicate** (S9) now lands in the editor.
- **Builder:** shop picker **never pre-selected** (Region → Shop, balance card); header warehouse (rewrites lines' warehouses, as legacy) + per-line warehouse with "N available" / "short by N"; product search (in-stock first) and a plain fallback select; qty / rate / discount per line
  with strict parsing (`parseRupees`, ≤ 3 decimals for bags, Urdu digits accepted), move / delete lines; invoice discount, freight, loading, other charges; **live totals from the shared `invoiceTotals`** (must equal the server's response to the paisa —
  a test proves it on random invoices); Amount Paid (disabled for drafts and without `PAYMENT_CREATE`; editing a posted invoice starts at what is already received and cannot go below it — the server names the receipt otherwise), method, reference, description, note.
  Price hints: default rate = `sellP` else `lastRateP`; below-cost / below-minimum / low-margin hints **only** when the picker returned cost fields (`PROFIT_VIEW`). **Save draft** / **Save** (post) / Discard; a new invoice starts with a fresh `idempotencyKey`, regenerated after success.
- **Editing a posted invoice:** confirmation dialog first (legacy wording adapted: "adjusts stock and the shop's balance by the difference"), shop locked with the hint to use Change shop, `revision` sent, **a stale revision shows the server's message verbatim and offers "Reload"**,
  the "cannot go back to draft" rule means there is no Save-draft button on a posted invoice.
- **Errors:** the 422 `errors[]` lines in a banner exactly as the legacy did (verbatim from the server), field-level marks where the message names a line ("Line 2: …"); a 403 (no `PAYMENT_CREATE`) explains the whole save was refused; network failure keeps the form intact.
- **Unsaved-changes guard** (leaving with edits asks first), double-click safe (button disabled + key), keyboard flow (Enter in qty adds the next line as legacy did if it did; otherwise Tab order sane), Urdu names `dir="auto"`, no emoji, themed tokens, **phone layout at 390 px** (lines as cards, totals sticky or clearly reachable, no page-level horizontal scroll).
- **After Save:** go to the view page (S9) with a toast showing the number; the list, statement and balances refresh.
- **The e2e dataset** from S9 is reused; add what the builder specs need (products with stock in two warehouses, one with a set price, one with only a last rate, one below cost for a `PROFIT_VIEW` role, one product with stock 0).
