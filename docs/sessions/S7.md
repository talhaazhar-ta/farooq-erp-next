## Planner decisions after S6 (binding)
1. **Cancel journal:** a reversing entry with `source_type` `INVOICE_CANCEL` (same `source_id`), **dated the invoice's own date** — the same rule as S3's
   payment reversal, so the pair cancels at every date and the legacy ledger (which simply skips CANCELLED invoices) agrees at every date. Statements
   **omit both entries** of a cancelled invoice, as they omit a reversed voucher; add it to S4's `omittedReversed`-style count (rename the field only
   additively, e.g. `omittedCancelled`, so S5's screens keep working). Add `invoiceCancelLines` next to `invoiceLines` in `ledger.ts`.
2. **Edit posted — journal:** rewrite the invoice's one `INVOICE` entry in place (`replaceEntryLines`, like S3 `editAmount`) to the new total and the
   new invoice date. The legacy ledger reads `grandTotal` and `invoiceDate` live, so this is the equivalent. Audit before/after carries the old figures.
3. **Edit posted — stock:** compute the difference **per product × warehouse** (old lines vs new lines), not per line, and post one movement per
   non-zero difference: `SALE_OUT` for more bags, `SALE_REVERSAL_IN` for fewer, `ref_type` `INVOICE_EDIT`, dated the (new) invoice date as the legacy
   did. A migrated invoice (`migrated = true`) posts **no** stock movement on edit or cancel (nothing was ever taken). No `source_item_id` column — it is
   not needed (edits are refused once a return exists, and M5 will link returns to `invoice_items` directly).
4. **Cancel — stock:** `SALE_REVERSAL_IN`, `ref_type` `INVOICE_CANCEL`, **dated today's business date** (legacy), per product × warehouse for
   Σ(qty) of the lines; returns are impossible here because cancel is refused while a non-cancelled return exists.
5. **Stale edits:** `PUT /invoices/:id` requires the `revision` the client loaded; a mismatch is refused (422, `This invoice was changed by someone
   else since you opened it. Reload it and make your change again.`). Legacy used `clientOpId#revision` for the same purpose.
6. **`allowNegativeStock`** is read from `company_profile.doc` (the imported legacy settings); missing = false.
7. **Payment at the time of sale:** extract the receive core of `PaymentsService` into one internal function that takes the caller's transaction
   (`writeReceipt(tx, actor, {customerId, amountP, method, reference, date, note, allocations})`), and have **both** `receive` and the invoice post call it —
   one code path, S3's tests unchanged. The allocation goes to this invoice only, amount = the paid delta; it must still pass S3's caps.
8. **`previous_balance_p`:** the shop's journal balance **at the moment of posting**, excluding this invoice (legacy: live balance at save time — not as of the
   invoice date). Frozen afterwards; only Change shop recomputes it (legacy rule, new shop's balance the day before the invoice date).
9. **Snapshots:** a post or an edit re-takes the shop / region / warehouse snapshots and the line product snapshots (legacy `customerFields` / `snapshotItem`
   run on every save); Change shop re-takes the shop snapshots.

## Goal
Server-side `InvoicesService` in `apps/api`: **save draft, post, edit a posted invoice, cancel, duplicate, change shop**, each in one
transaction, with the legacy validation messages verbatim, the owner's decisions enforced, stock and journal and payment-at-sale written
together, and a ledger-bridge proof like S3's. No UI (S9), no search/print (S8).

**Prerequisite:** S6 done (lines, stock levels/movements, `invoiceTotals`, `ledger.ts` invoice builder). Baseline green first.

## Owner decisions (2026-09-24 — enforce, test, and don't reopen)
1. **Cancel with money received is refused** while any POSTED payment is allocated to the invoice; the message lists the receipt numbers
   (staff reverse them first). No silent shop credit.
2. **Permissions:** create / save draft / edit a draft / post = `SALES_CREATE`; edit a **posted** invoice, cancel, change shop = `TRANSACTION_CORRECT`;
   taking money at the time of sale additionally needs `PAYMENT_CREATE` (SALES has both). ACCOUNTANT has no `SALES_CREATE` (can correct, can't
   create). INVENTORY: none.
3. **Editing a posted invoice is allowed as a net correction** (stock and balance move by the difference, one transaction), **refused once the
   invoice has a non-cancelled return or a dispatch**, and a posted invoice can **never go back to DRAFT**.

## Rules (ported / fixed — each gets a test)
- **Validation** — the legacy messages verbatim (shop, warehouse, at least one line, product exists, qty > 0, rate not negative, rate required
  unless draft, discount ≤ line amount, stock "Only X bags of P are available in W. Requested: Q.", paid ≥ 0, paid ≤ total with the legacy
  wording). **Stricter:** negative item/invoice discount and negative freight/loading/other charges are refused; quantities > 3 decimals refused.
  Stock check: **per product × warehouse totalled across lines** (legacy checked per line — two lines of the same product could oversell;
  record), skipped for drafts and when the company setting `allowNegativeStock` is on, and on edit **counts this invoice's own previously
  deducted bags back in** (legacy bug 5).
- **Draft:** any number of drafts; no number, no stock, no journal, no payment. Editing a draft needs `SALES_CREATE`.
- **Post** (new or from a draft): number `INV-<business year>-<6>` via S3's `nextNumber` in the same transaction; lines saved with stable ids;
  `cost_snapshot_p` per line = port of `Inventory.costOf(product, lineWarehouse)` as a **read** over `stock_levels` / movements (fallback order as
  legacy; test each branch); `SALE_OUT` movement per line (`source_type` INVOICE, `source_id` = the invoice) updating `stock_levels` in the same transaction; journal via
  the shared invoice builder; `previous_balance_p` = shop's journal balance excluding this invoice, frozen at first posting; status from
  `invoiceTotals` + paid; audit `Invoice created` (or `Invoice edited` for a draft being posted — legacy wording); snapshots of shop/region/warehouse.
- **Payment at the time of sale:** `paidAmount > 0` → one receipt through the **same code path as `PaymentsService.receive`** (REC number, method,
  reference, date = invoice date, note `Received with invoice <number>`, one allocation to this invoice, journal, audit) inside the invoice's
  transaction. Needs `PAYMENT_CREATE` (403 otherwise, whole save refused).
- **Edit posted** (`TRANSACTION_CORRECT`): refuse if cancelled (legacy: "A cancelled invoice cannot be edited. Duplicate it instead."), if any
  non-cancelled return or a dispatch exists (new wording, say why), if the shop changes (legacy wording pointing to Change shop), if asked to go
  back to draft. Net correction: line diff by stable line id → movements for the **difference only** (legacy did full reverse + re-deduct; the net
  is the same except for migrated invoices, which must never get stock "back"); journal entry rewritten to the new total (like S3's editAmount);
  paid raised → extra receipt for the delta (legacy); paid **lowered below what is allocated → refused** with a message telling staff to reverse
  the receipt (legacy silently let the two disagree). Revision + audit before/after.
- **Cancel** (`TRANSACTION_CORRECT`): reason required; refused with receipts (owner decision 1); refused if a non-cancelled return exists
  (restocking would double-count returned bags — legacy bug); stock comes back for (qty − returned) per line (`SALE_REVERSAL_IN`,
  `INVOICE_CANCEL`); journal: reversing entry per planner decision 1; cancelling a draft just marks it; a cancelled invoice keeps its number.
- **Duplicate:** new draft, today's date, paid 0, due date / order / dispatch / reference blank (legacy `duplicate`).
- **Change shop** (`TRANSACTION_CORRECT`): port `reassignCheck` refusals and messages verbatim (cancelled; any non-cancelled return; a receipt
  not wholly applied to this invoice) and `changeCustomer` effects (invoice snapshots; wholly-applied receipts move with it incl. their
  snapshots and journal party lines; `previous_balance_p` recomputed as the new shop's balance the day before; stock and number untouched);
  audit `Invoice moved to another shop`. Drafts refused (legacy UI refuses).
- **Idempotency:** `idempotencyKey` on post/save like S3 (replay → first result). **Concurrency:** two posts racing for the last bags → one
  succeeds, one gets the stock message; lock `stock_levels` rows in a fixed order.
- **Dates:** business dates only (`businessDateOf`), invoice date may be in the past; number year = current business year.

## API (shapes in `@farooq/shared`, `.strict()`, 422 `{message, errors}`)
`POST /invoices` (draft or post), `PUT /invoices/:id` (edit draft or posted), `POST /invoices/:id/cancel`, `POST /invoices/:id/duplicate`,
`POST /invoices/:id/change-shop`, `GET /invoices/:id` (header, lines, payments, allocations, stock effect, `actions {edit, cancel, changeShop}`
each `{allowed, reason}` like S3), `GET /products?q&warehouseId` (picker: names en/ur, brand, pack, price hints: set price, last invoiced rate,
min price, and available qty per warehouse; cost/margin fields **only** for `PROFIT_VIEW`), `GET /warehouses`.
