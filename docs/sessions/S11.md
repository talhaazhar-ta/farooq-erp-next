## Goal

Make the database hold a purchase (supplier bill) **as the legacy app has it** — header, lines, the bags it received and the cost it gave those bags —
and prove the import exact, like S6 did for invoices:
1. every purchase's total **recomputed from its lines** (the legacy reuses `Calc.invoice`, i.e. our `invoiceTotals`) equals its stored `grandTotal`;
2. **purchase ↔ stock:** for every purchase, the net of its stock movements per product × warehouse equals the bags its lines say were received;
3. **average cost:** a shared port of the legacy purchase-history average recomputes every stored `inventory.avgCostP` that has a purchase line behind it;
4. shop / supplier balances, statements, invoices and stock still reconcile with **0 differences**.

S12 builds the purchase service on this (create / edit / pay at purchase / average-cost maintenance); S13 list / view / print; S14 the builder.

**Prerequisite:** M2 done (it is). Baseline first: `pnpm install && pnpm build && pnpm typecheck && pnpm lint && pnpm test && pnpm e2e` — expect **1,109** unit tests and
**165** Playwright tests green, and check the exit code. The walkthrough by a person (STATUS "Next step" 1) is **not** a blocker for S11 (no screens) — it blocks S13.

## User decisions for M3 (2026-09-25 — binding, don't reopen)
1. **Average cost is maintained in M3** (not M4), ported from the legacy purchase-history average (below). S11 ports and **proves** it; S12 writes it.
2. Permissions (S12): create = `PURCHASE_CREATE`; edit = `PURCHASE_CREATE` **or** `TRANSACTION_CORRECT` (legacy `canEdit`); paying at the time of purchase also needs `PAYMENT_PAYOUT`.
3. **Four legacy bugs are fixed, not ported** (each needs a test when its session builds it; S11 owns #3):
   1. a new purchase accepts `paid > total` and a negative `paid` (S12);
   2. a line discount above the line amount (S11: CHECK + importer refusal; S12: validation message);
   3. **part delivery overstates the unit cost** — legacy `Cost.allocate` divides the line total by the **received** bags (`basis = received || qty`); the fix divides the line value
      by the **ordered** bags (the bill is for what was ordered). Charges stay spread per received bag. Real data has no part delivery, so the fix changes no real figure — prove that;
   4. the print labels ordered bags "Bags received" (S13).
4. **No purchase drafts, no cancel, no delete, no separate "Change supplier"** (legacy has none). The supplier changes only inside an edit while nothing is attached (S12).
5. `receiveMore` (later delivery) is **not ported** — no screen calls it.

## Scope

### 1. `packages/shared`: `purchase-cost.ts`
A pure port. Paisa in, paisa out; quantities in integer thousandths, like `invoice-totals.ts`.
- `allocateCharges(lines, chargesP)` = `Cost.allocate`. It returns per line `goodsUnitP`, `chargeShareP` and `landedUnitP`. **Fix 3 applies:** the goods unit = line total ÷ **ordered** bags. The legacy rounding is otherwise exact.
  - Say in a comment exactly where the fix differs and why.
  - Add a test pinning the legacy figure beside the fixed one for a part delivery.
- `unitCostForAverage(line, basis)` = the per-line unit that `Landed.weightedAverage` (basis `LANDED`) or `Cost.weightedAverage` (basis `PURCHASE`) uses:
  - the goods unit = the stored `goodsUnitCost`, else line total ÷ quantity, else unit price;
  - under `LANDED`, add `round(chargeShare / q)` and `round(operationalShare / q)`, where q = received bags.
- `weightedAverage(lines, basis)` → the rounded average, or `null` when no received bags exist ("keep the old one" is the **caller's** rule — document it).
- Table tests from the legacy tests plus property tests:
  - the charges are conserved within rounding;
  - no line is negative;
  - with no charges and no operational share, the average equals the plain goods average.

### 5. Reconciliation (`packages/import/src/reconcile*.ts`) — three new checks, exit non-zero on any mismatch
1. **Purchase totals.** Every non-cancelled purchase's `subtotal`, `discountAmount`, `taxAmount`, charges, `grandTotal`, `totalQty`, `lineCount` and each line total must **recompute from its lines** with `invoiceTotals`.
   - Use the legacy `toDraft` split for the overall discount.
   - Report per purchase.
   - Migrated purchases are informational, as S6 did for invoices.
2. **Purchase ↔ stock.** Per purchase × product × warehouse, Σ `qty_delta_milli` of movements with `source_type = 'PURCHASE'` must equal Σ the lines' received bags.
   - A non-cancelled purchase counts. A cancelled one must net 0.
   - Migrated ones are skipped and listed.
   - The two real edited purchases prove the reverse-and-re-add history nets out.
3. **Average cost.** For every `stock_levels` row (bucket `stock`) that has at least one non-cancelled purchase line with received bags, `purchase-cost.weightedAverage(lines, basis)` must equal the imported `avg_cost_p`.
   - The basis comes from the settings.
   - A row **without** such a line is listed as "kept from before (no purchase line)" — not failed. It is informational, like migrated invoices.
   - **Also prove the substitution S12 will rely on:** each line's `operational_share_p` = Σ `additionalCost` of the non-cancelled `inventoryCostAdjust` rows for that `purchaseItemId`, whose landed cost is not cancelled. Read those rows from the backup JSON, since the stores are deferred.
   - Also prove each line's `landed_unit_cost_p` = goods unit + round(`chargeShare / q`) + round(`operationalShare / q`) when set.

   If the real data breaks any of these, **stop and write down exactly which rows and why** in STATUS. Don't loosen a check to make it pass.

Add each new check to the safety-net suite (`invoice-stock-safety-net` style): one "bite" test per check that corrupts one field and sees the reconciliation fail.
