### Behaviour worth knowing
- **Received:** blank = the whole line and **nothing is sent** (`receivedQuantity` only when the box was filled in); a figure = a part delivery; `0` = the bill only — the hint says it puts no bags into stock and warns the delivery would be **counted twice** if the warehouse also records it; more than ordered is allowed (stock takes them all, the bill stays for the ordered bags). When every line is 0 the button says "Save order (no stock)".
- **Edit is a full PUT:** carries the `revision`, every line id, driver / delivery ref / bill / vehicle; `description` is **always sent** (an omitted one is KEPT by the server, so clearing the box has to say so). A line that arrived whole opens with Received blank.
- **Lines tied by a return or landed cost** cannot be removed, keep their godown when the header warehouse changes, and show the server's reason; a Received figure below the bags already returned is called out before the click.
- **Amount Paid:** starts at what has been paid, with the legacy hint verbatim; a lower figure is called out and refused by the server naming the voucher; raising it records one voucher for the difference; disabled (with the reason) without `PAYMENT_PAYOUT` — no role that can save lacks it, so that one is unit-tested, not e2e-tested.
- **Last rate:** a NEW line starts at the last rate paid for the product (never over a typed one) with "Last bought at PKR 3,300.00/bag on 26 Sep 2026 (PUR-…)"; lines already on the purchase get no hint (a screenshot showed an edited line being told its own rate — fixed).
- **Double click:** the disabled button and a `busy` ref both stop it; the mutation check shows the test only bites when both are removed (two layers).

## Deviations from the plan / decisions
1. **The supplier is a search combobox, not a select** (there is no region filter for suppliers); the driver and delivery reference are on the form because an edit is a full PUT and would clear them.
2. **Payment method is asked on an edit too** ("for what is added").
3. **The e2e dataset grew** (11 suppliers `supSahiwal … supSwat`, the 4 "E2E Buyer …" products — named without "Builder" and without the Urdu word S10 searches for — and one shop `buyerShop`); `stockBasics` skips "E2E Buyer …". The edit test buys into the SECOND godown so the average-cost figures are exact.
4. A driver name used by `purchases.spec` ("Nawaz") collided with its "search finds exactly one" test — found by running both specs together; the builder spec uses another. Playwright runs `purchases-builder` before `purchases`, so its purchases exist when the S13 list specs read the list: they compare with the API, and the builder's suppliers / products / driver words are distinct from theirs.
5. No cost preview on the form (the landed cost is on the saved purchase, `PROFIT_VIEW`); the product's "extra cost per bag" is never part of a purchase figure (S14).
