## S9 — what was done (M2 part 4: reading and correcting invoices on screen)

A signed-in person with the right role can now, in `apps/web`, **list and search invoices** (`/invoices`), **open one** (`/invoices/:id`), **print it** (`/invoices/:id/print`, classic and standard layouts), and **discard a draft, cancel, duplicate and change the shop** of an invoice — all on S7's write API and S8's read API, driven and checked in headless Chrome. The statements screen now shows what each invoice was for and its bags, and the Receive panel says what each unpaid invoice is. **No builder** (no "New invoice", no Edit, no Post — S10). The live ERP is untouched; nothing is deployed.

### How closely the print matches the legacy (and where it does not)

Read from the legacy code (`04-documents.js` standard layout + `Paper.css`, `08-classic-invoice.js`) — **the old ERP was not run in a browser**, and no sheet was printed. The block order, the six-row box with its blank fifth row, the ledger table, the classic serial / `InvNo`, ribbons, footer, meta rows skipped when empty and the CSS values are ported one for one. **Differences:** the Urdu font stack falls back to system fonts (`Noto Nastaliq Urdu`, `Jameel Noori Nastaleeq`, `Noto Naskh Arabic`, Segoe UI, Tahoma) with `line-height 1.5` (the legacy 1.7 made the standard sheet run to two pages); the standard layout's base size is 10.5 px, not 11 px, and its spacing a little tighter, for the same reason; the standard sheet's few captions the model does not carry (`Owner`, `Customer code`, `Mobile`, `WhatsApp`, `Address`, `Region`, `Market / route`, `Payments against this document`, `No lines on this document.`) are typed in the component as the legacy typed them; the running page footer is a `position: fixed` line in print only; the sheet sits in a scroll box on screens narrower than 210 mm.

### S9 deviations from the plan (all deliberate)

1. **Status pill + payment word:** the list shows the payment word ("Partly paid") under a status only where it adds something ("Confirmed" + "Partly paid"); the detail does the same.
2. **Cancel / Discard reason is required for a draft too** (the server requires one for both).
3. **Discard / Cancel return to the list with a toast** (as planned); **Duplicate lands on the new draft's view page** — S10 will send it to the editor.
4. **`useSearch` returns the raw address** even when `validateSearch` sanitises it (found by an e2e test: `?template=<script>` went to the API and came back 422). Every screen that takes a value from the address re-parses it; the print screen now does too.
5. **The Receive panel line summary is checked in e2e** (the panel's `alloc-summary` against the API's `lineSummary`); S5's panel unit tests were not changed.
6. **The e2e dataset merged S8's invoices and S4's payments** instead of replacing S4's (the plan said "rebuild on `synthetic-invoices.ts`"): S5's payments specs need the 300 payments with supplier payments, refunds and reversals, which S8's backup does not have.

### Findings worth knowing

- **PDF text extraction of letter-spaced headings has gaps** (`I N V O I C E`, `C A N C E L L E D`), so the print specs compare with whitespace removed and case-insensitively where the CSS upper-cases a label. The Urdu labels are proven present as Arabic-script glyphs and, on the screen, character for character from the constants; the *shape* of the glyphs is proven only by the screenshots.
- **A discarded draft is a CANCELLED invoice with no number.** It prints with the CANCELLED ribbon and no number (right), but a spec that assumed "the first cancelled invoice has a number" failed in the full run once another spec had discarded a draft (fixed by picking a numbered one).
- **The stale-page refusal path is real:** the panel offers Change shop from data a moment old; the server refuses a receipt that also paid another invoice; the panel shows its words and stays open (tested by opening the page first, then splitting a receipt over two invoices).
- Specs that move money each own a shop and create their invoices through the API (`postInvoice`), reading every expected figure back from it.
- The web bundle is now 575 kB in one chunk (no code splitting yet; Vite warns).
