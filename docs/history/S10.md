## S10 — what was done (M2 part 5: creating and changing invoices on screen)

A signed-in person with the right role can now, in `apps/web`, **make a new invoice** (`/invoices/new`), **save it as a draft** (any number of drafts), **edit a draft**, **post it** (with money taken at the sale), **post a saved draft straight from its page**, and **edit a posted invoice** (`/invoices/:id/edit`) — all on S7's write API, driven and checked in headless Chrome against the real server. Duplicate now lands in the editor. The live ERP is untouched; nothing is deployed.

### What exists now

- **Form logic** (`lib/invoice-form.ts`, pure, the unit-tested core): the form holds what was typed (text); `formReducer` (add / move / remove lines, **header warehouse rewrites every line**, **region clears the shop**, the shop starts empty); `parseQuantity` (≤ 3 decimals, Urdu digits, read as text into thousandths) and `parseAmount` (`parseRupees`, blank = 0); `formTotals` = the shared `invoiceTotals`; **`detailToForm` / `formToSavePayload` are the ONE pair** used by edit, duplicate-then-edit and the direct Post (`postPayloadOf`); `stockByPair` (per product × warehouse **totalled across lines**, the invoice's own deducted bags counted back on an edit via `ownBagsBack`); `priceHint` (below cost / below minimum / low margin / no cost — nothing at all unless the role may see cost); `isDirty` (form vs. snapshot, not "a key was pressed"); `splitErrors` (line-numbered messages vs. general).
- **Screens** (`routes/invoice-builder.tsx`, `components/invoice-builder-parts.tsx`): shop section (Region → Shop combobox, never pre-selected, a card with owner / mobile / region / current balance; **locked with the "use Change shop" hint on a posted invoice**), header (warehouse, date, due date, order number), **product search** (English / Urdu / brand / category / SKU / bag size, in-stock first for the warehouse, results marked busy while a new answer loads, plain-list fallback), **lines** (table ≥ 768 px, cards on a phone — one representation in the DOM — with warehouse + "N available · short by N", Qty / Rate / Discount, amount, price hint, move / remove, the row marked and its message under it when the server names a line; **Enter moves to the next box**; adding a line puts the cursor in Qty), charges & payment (overall discount, freight, loading, other, **Amount Paid**, method, reference, description / تفصیل, internal note), summary card and a **sticky bar** (grand total + Discard / Save draft / Post invoice, or Cancel editing / Save changes on a posted invoice).
- **Save**: one request per click (button disabled + a busy ref), a fresh idempotency key that is **kept when a save fails and replaced after a success**; refusals shown **verbatim, every line**, under "This invoice cannot be saved yet — nothing has been changed", form untouched; a network failure says nothing was saved and keeps the form; a stale revision shows the server's sentence and a **Reload** button (rebuilds the form from a fresh copy, no second question); after success → the invoice's page with a toast (the number) and lists / statements / balances / product stock refetch.
- **Editing a posted invoice** asks first ("Edit a confirmed invoice?" — legacy wording), sends the `revision` as loaded, keeps line ids, starts Amount Paid at what is received, has no Save-draft. `/invoices/:id/edit` for an invoice the server will not let this role edit shows `actions.edit.reason` verbatim instead of a form. The edit copy is loaded once and **never refreshed behind the person's back**.
- **View page:** exactly three additions, all drawn from `actions.edit`: **Edit** (never hidden — disabled with the server's reason), **Post invoice** (drafts; confirmation states a number is assigned, bags leave stock, the balance goes up; one `PUT … mode: "post"`, paid 0, revision as loaded, fresh key; refusal shown in the dialog), and the list's **New invoice** button for `SALES_CREATE`.
- **Unsaved-changes guard** (`components/unsaved-guard.tsx`): router blocker + `beforeunload`, "Leave without saving?" / Keep editing; a successful save and a discarded draft let the next navigation through.
- **Server, two small changes:** `GET /products?ids=` (comma-separated ids, ≤ 100, active or not — so an edited invoice's lines get stock hints; `productPickQuerySchema` in `packages/shared`); **the CORS methods fix** (below). Nothing else on the server changed.
- **e2e dataset:** five "Builder …" products (`BUILDER_PRODUCTS`, imported through the real importer with their stock and cost) and eleven new shops (Papa … Zulu).

### A real bug the browser found (fixed)

**No invoice could be edited from the web app.** The API's CORS preflight answered GET / HEAD / POST only (`@fastify/cors`' default), so the browser refused every `PUT` before it reached the server. Every server test and every S9 screen was unaffected (nothing PUT from another origin). Fixed in `apps/api/src/cors.ts` (`corsOptions`, used by `main.ts`), pinned by `api/cors.test` (7 tests; with the methods removed 3 go red).

### S10 deviations from the plan (all deliberate)

1. **`GET /products?ids=` and the CORS fix touch the server** (S9 had none): the first is what stock hints for an edited invoice need, the second was a bug that made editing impossible.
2. **The "last-invoiced-rate" product is proven by the spec posting an invoice through the API** (the dataset cannot give a product an invoice line without a whole invoice with stock and journal); the set-price, below-cost, zero-stock and tight-stock products are in the dataset as planned. "Below cost for a `PROFIT_VIEW` hint" is a product whose set price (Rs 500) is under its cost (Rs 900).
3. **Enter = next box** (the plan said to follow the legacy only if it had Enter handling; it has none, so Enter moves on and does not submit; Tab order is Product → Warehouse → Qty → Rate → Discount → next row).
4. **The product list closes after a product is added** (the legacy kept it open); the cursor goes to Qty.
5. **Save draft sends whatever is in Amount Paid** and the server's refusal ("Payment can only be taken when the invoice is posted…") is shown, rather than silently dropping the figure. The box is disabled only without permission to take payment; every role that can build holds that permission (S7 finding), so that rule is unit-tested, not e2e-tested.
6. **No tax entry on a line** (the legacy builder had none): a saved line's tax is carried as a fixed amount; changing the quantity of a taxed line does not re-scale its tax. The low-margin threshold is fixed at 5 % and the below-minimum hint is always on — the two legacy settings (`lowMarginWarnPct`, `warnBelowMinPrice`) are not visible to the screen.
7. **A posted invoice's edit is loaded once and never refreshed on its own** (no refetch on focus); a newer copy comes only from "Reload".
8. **Post invoice on the view page and Edit share `actions.edit`** (there is no `actions.post`): for an accountant on a draft both are disabled with "You do not have permission to create or post invoices."
