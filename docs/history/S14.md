### 2. `RECEIPT_EDIT_OUT` and the carried cost (`b2b0778`)
- **`packages/db/src/stock.ts`** — `RECEIPT_EDIT_OUT` added to `MOVEMENT_KINDS`, `STOCK_RECEIPT_EDIT` to `MOVEMENT_REF_TYPES`. **No migration needed:** `stock_movements` has CHECKs only on `bucket` and `qty_delta_milli <> 0` (test asserts the constraint list); kind / ref type / source type are plain text validated at the boundary.
- **Importer** (`prepare.ts`): accepts the kind and the ref type. `source_type` is the ref type (`STOCK_RECEIPT_EDIT`), `source_id` NULL — exactly like `STOCK_RECEIPT` today. The real shape (from `StockDocs.editReceive`): `kind RECEIPT_EDIT_OUT`, `refType STOCK_RECEIPT_EDIT`, `ref` = the receipt's `RCV-YYYY-NNNNNN`, `qtyDelta < 0`, `unitCostP: o.unitCostP || 0`, dated as the ORIGINAL receipt.
  New fail-loudly cases: a reversal that **adds** bags; a reversal with **no cost field** (missing / null).
- **`carriedCost`** rewritten to the legacy's new rule: damaged bucket and cost ≤ 0 / NULL skipped; a `RECEIPT_EDIT_OUT` with qty < 0 **subtracts** qty × cost; otherwise only carried kinds with qty > 0 count; the result is `round(cost / qty)` only when **both** the net qty and the net cost are > 0, else 0.
- **Fixture:** one receipt edit (`build-fixture.ts`, appended at the END of the movements so no existing `mv-N` id moved): RCV-2026-000004, p-1 @ wh-2, 30 bags @ 800.00 edited to 30 @ 900.00 — mv-31 `RECEIPT_EDIT_OUT` −30 @ 80,000 dated 2026-01-10, mv-32 `ADJUSTMENT_IN` +30 @ 90,000. Bags net 0 (p-1@wh-2 stays 32), carried cost by hand = (30×80,000 − 30×80,000 + 30×90,000) / 30 = **90,000** (85,000 without the subtraction). The fixture has 32 movements now; the hand-computed counts in six importer / api tests were updated (30 → 32, 41/39 → 43/41 in the invoice ledger bridge, kinds and cost counts in `invoice-lines-stock`).
- Editing a receipt itself is **M4** (`StockDocs.editReceive` / `canEdit` / `toDraft`, the net-change stock guard, the signed "adjusted" column of the movement report) — PARITY says so.

## Deviations and findings
- **`RECEIPT_EDIT_OUT` cost check is "the field must be present", not "> 0".** The plan said to refuse a reversal that "doesn't carry a cost". The legacy writes `unitCostP: o.unitCostP || 0`, so a receipt line that never had a cost produces a legitimate reversal with cost 0 — refusing it would abort a real import. A missing / null field, a positive quantity and a fractional cost abort; an explicit 0 imports (stored as NULL, "no cost recorded", exactly as every other 0 cost). A test proves the guard is real (the same edit made valid still imports).
- **The fixture's p-1 has an extra of 2,000** (the S6 price-panel data), so the sale cost of p-1@wh-2 in `receipt-edit-fixture` is 82,000 (80,000 + 2,000). My first expectation (80,000) was wrong, not the code.
- `costP` on `GET /products` **changed meaning for `PROFIT_VIEW`** (stock cost → stock cost + extra) — intended (the legacy note and the invoice snapshot agree), the S10 builder reads it for the hint only. The stored `buyP` is still the price-panel figure.
- The prices panel's **double-count warning** (Landed-cost charges and an extra on the same product count the transport twice) is not ported — products are edited only in the old ERP; noted in PARITY for the products milestone. The owner should still be told: use the extra **or** the landed cost for a product, not both.
- The legacy movement report's "adjusted" column became a signed net (`b2b0778`); the rebuild has no such report yet — PARITY row → M4.
- `bfa4b25`: **not applicable** (the rebuild keeps no browser copies). PARITY change log updated for all three commits.
